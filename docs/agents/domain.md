# Domain docs

This is a single-context repo. The root `GLOSSARY.md` defines domain
terms; `docs/adr/` contains architecture decisions.

Before exploring an area, read the glossary and relevant ADRs if they
exist. Proceed when they do not. The domain-modeling skill creates
these files when terms or decisions are resolved.

Use glossary terms in issues, tests, and design work. Surface a
conflict with an ADR explicitly before changing its decision.
