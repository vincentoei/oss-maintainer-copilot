## What the scored application sends

The fixed report calls `POST /v1/chat/completions` with temperature 0, up to 256 output tokens, and the report's JSON Schema in `response_format`. The application parses only `choices[0].message.content`, then validates the selection. In Ollama 0.40.16 the adapter forwards the schema to the generator and maps `max_tokens` to `num_predict`. A schema-valid selection can still choose the wrong issue type. [Application client](../../../src/maintainer_copilot/model.py) · [Frozen comparison](../issue-62/protocol.md) · [Ollama 0.40.16 adapter](https://github.com/ollama/ollama/blob/v0.40.16/openai/openai.go#L707-L760)

The application omits a thinking override. On this endpoint `reasoning_effort: "none"` requests disabled thinking. Omitting it leaves Ollama to resolve the model default. Its native chat endpoint uses the separate field `think`. Google describes a template token to enable thinking and Qwen describes thinking by default in its upstream template. Each installed artifact's `/api/show` thinking descriptor, if present, gives the values and default for Ollama. A test with an added override would measure a changed request. The OpenAI adapter exposes a separate `message.reasoning` field, so completion tokens and the termination reason help interpret a response with empty final content. [Ollama thinking](https://docs.ollama.com/capabilities/thinking) · [Ollama 0.40.16 effort handling](https://github.com/ollama/ollama/blob/v0.40.16/openai/openai.go#L543-L576) · [Response conversion](https://github.com/ollama/ollama/blob/v0.40.16/openai/openai.go#L301-L329) · [Google model card](https://huggingface.co/google/gemma-4-E2B-it) · [Qwen model card](https://huggingface.co/Qwen/Qwen3.5-4B)

Set the comparison's context on the local model alias with `PARAMETER num_ctx 16384`. Once loaded, `/api/ps` exposes the active `context_length`, `size` and `size_vram` for checking context allocation and offload. The registry alone establishes neither 16K GPU residency nor completion within the application's 20-second timeout. ## Optional Ministral fit screen

The RTX 5060 Laptop GPU reported 8,151 MiB total and 7,883 MiB free before inference. The Ministral GGUF model layer occupies 5,743 MiB on disk. With one sequence, full attention and a 16-bit KV cache, 34 layers × 8 KV heads × 128 dimensions × 16,384 positions × 2 (keys and values) × 2 bytes gives another **2,176 MiB**. Treating model-layer bytes as a weight-residency estimate gives **7,919 MiB** before scratch buffers, already 36 MiB above the observed free memory. Some stored tensors may stay unloaded on text-only requests. Runtime allocation and cache implementation can change that estimate. This is enough to defer the optional download; actual 16K residency remains unmeasured. CPU offload, shorter context or cache requantization would change the serving comparison.
